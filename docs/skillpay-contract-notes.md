# SkillPay 合同审阅：售卖自有 SKILL 与开源/闭源切换

> 基于《资源商品售卖技术服务协议》文本的工程与产品风险审阅，不构成法律意见。正式签署或大额商业化前应由律师复核。

## 结论

合同没有禁止商家出售自己开发的 SKILL，也没有出现“必须开源”或“禁止闭源”的条款。SKILL 被明确列为可上架的虚拟资源商品，平台提供的是计收费、上架下架、调用与履约协同等中立技术服务。

卖自己写的开源 Skills 在合同层面本身成立；需要控制的不是“是否开源”，而是四件事：

1. 对商品、适配接口/方案/文档拥有完整知识产权或合法授权；
2. SKILL 源文件、密钥、令牌等敏感信息不能出现在公开仓库、前端代码、日志或买方可获取内容里；
3. 商品上线后的运行、履约、售后、争议、AI 输出与误判责任由商家独立承担；
4. 已公开的开源版本与许可证不能靠页面开关追溯收回；页面开关只影响后续售卖配置与本地管理口径。

## 关键条款与影响

| 合同位置 | 原文要点 | 影响 |
|---|---|---|
| 一、定义 3 | 商品包括 SKILL、应用程序等虚拟资源商品 | SKILL 明确是可售卖商品类型 |
| 一、定义 9 | 敏感信息包括 SKILL 源文件等核心内容 | 闭源 SKILL 的源文件、密钥、token 不能写入公开仓库、商品文件、前端、日志或文档 |
| 二、服务内容 1 | 商品内容包括但不限于 SKILL 文件；平台生成收款技能文件并按配置交付 | 上架前确认交付包里没有不该暴露的东西 |
| 二、服务内容 2 | 商品合法性、合规性、可用性及权属由商家负责 | 自写 Skill 可以卖，但必须能证明权属 |
| 二、服务内容 4 | Agent/SKill 的自主输出、决策、错误执行责任由商家承担 | 需要测试、限权、超时、审计和失败兜底 |
| 二、服务内容 7 | 可自行决定版本更新、迭代或调整收费标准；调价不影响已完成调用和有效期内订阅 | 开源改闭源可作为后续版本/配置调整；不能追溯改变已成交订单权益 |
| 三、规范 5 | 商品须权属清晰、不侵权、不含恶意代码或注入性指令 | 上架前做依赖审计和 prompt 注入检查 |
| 三、规范 6 | 不得在公开仓库、日志、文档等买方可获取内容中明文写入敏感信息 | 公开仓库里的历史版本不会自动变私有 |
| 三、规范 11 | 停服或停止提供商品须提前 30 天书面通知并退还未使用费用 | 长期不维护也要走停服与退款流程 |
| 四、知识产权 2 | 商家确认对商品及适配内容拥有完全自主知识产权或合法授权 | 混用第三方组件时要核对许可证和署名 |
| 四、知识产权 4 | 平台为服务可做必要存储、展示、路由、复制、调用；不改变权属 | 平台上架不等于把代码版权交给支付宝 |
| 四、知识产权 5 | 不就买方使用商品形成的运行结果主张权利；运行结果不含 SKILL 源文件 | 可对源文件保权；不能拿用户运行结果主张额外权利 |

## “开源改闭源”的正确理解

页面上的“开源/闭源”是 **SkillHub 本地管理与后续售卖配置**，不是法律状态的万能开关：

- 可以把某个 Skill 标记为闭源，用于后续上架包、文档展示和收费配置；
- 不能把 GitHub 上已经公开的历史提交、已发放的开源许可证、已购买用户手里的副本“改成闭源”；
- 如果仓库已有 `LICENSE`（MIT/Apache/GPL 等），要按原许可证继续履约；想闭源，应发布新版本、切换许可证，并明确旧版本继续按旧许可证存在；
- 如果 Skill 由多人贡献或含第三方组件，要确认有权单方改许可证；否则只能对自己拥有权利的部分闭源。

## 上架前操作清单

1. **权属**：确认 SKILL.md、脚本、文档、prompt、配套资源均为自有或有商业使用授权。
2. **依赖**：列出第三方依赖及许可证，处理 GPL/AGPL/商用限制/署名要求。
3. **敏感信息**：扫描公开仓库、日志、商品包、frontmatter、README，确保无 API key、token、私有地址、闭源源文件。
4. **交付包**：闭源商品只上传必要交付文件；开源版本和闭源版本分仓或分版本管理。
5. **行为边界**：Skill 不能诱导越权、绕过安全限制、抓取/滥用接口、注入误导买方 Agent 的指令。
6. **履约**：写明版本、功能、限制、售后范围；变更收费不得影响已有订单和有效期内订阅。
7. **退出**：停止维护或下架前 30 天通知买方和支付宝，处理未使用费用退款。

## SkillHub 落地口径

- `origin: opensource:*` 默认 `open`，其余默认 `closed`；显式标注优先。
- 公开 GitHub 仓库不等于有开源许可证，因此不把 `own-public` 当作默认开源依据。
- 页面和 CLI 的切换写本地 SQLite，只影响 SkillHub 的管理口径。
- 不自动改 GitHub 可见性、LICENSE 或支付宝商品配置。
